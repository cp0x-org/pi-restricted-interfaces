# P3: проверка интерфейсов по странам через прокси

Скрипт `monitor/scripts/probe.py` делает HTTP-запросы (без JavaScript) к главной странице каждого интерфейса и к известным
гео-эндпоинтам (`geo_endpoints` в `data/interfaces.json`) из выбранной страны через прокси, проверяет, что прокси действительно
находится в этой стране, и пишет наблюдения. Наблюдения попадают в `data/observations.json`, оттуда `build.py` берёт последние
подтверждённые и показывает их на сайте как основание вердикта `observed`.

Что проба доказывает: блок на уровне edge/сервера для страны X в момент T с данного типа сети. Чего не доказывает: отсутствие блока
(статус `served` значит лишь «edge не заблокировал»; клиентские гейты, скрининг кошелька и гейты по активам проверяются
следующими этапами, см. `roadmap.md`, P4/P5).

## 1. Какие прокси нужны

| Тип | Зачем | Нужно сейчас |
|---|---|---|
| **Резидентные** с таргетингом по стране (и по штату/провинции для US-NY, CA-ON) | основной вантаж: обычные домашние IP, не срабатывают VPN-детекторы | да |
| Датацентровые | намеренно: проверить, есть ли VPN/DC-детект (Sky, Euler, Polymarket) | позже; хватит любого дешёвого провайдера или собственного VPS в нужной стране |
| Мобильные | строгие детекторы репутации IP | позже |
| Tor | Lido переводит Tor в limited | локальный `tor`, бесплатно |

Резидентные прокси продаются по трафику (за ГБ). Для P3 трафик крошечный: главная страница без JS плюс пара JSON-запросов,
порядка 10–20 МБ на страну, то есть **0,2–0,4 ГБ за полный прогон 57 интерфейсов по 20 странам**. 1–2 ГБ хватает на
несколько полных прогонов; еженедельные прогоны укладываются в единицы долларов в месяц. Будущий браузерный прогон (P4)
дороже: 1–3 ГБ за полный проход при блокировке картинок и шрифтов.

Санкционные юрисдикции (IR, KP, SY, CU, оккупированные регионы) коммерческие провайдеры не продают, а использовать такие
выходы юридически сомнительно. Для них в каталоге остаётся основание `inferred` по коду и конфигам.

| **Decodo** (бывший Smartproxy) | ≈ $3,5–4 / ГБ, дешевле на объёме | карта; крипто для резидентных не подтверждено | таргетинг страна / штат / город, 3-дневный пробный период, понятная документация. Рекомендуемый старт |

| **DataImpulse** | ≈ $1 / ГБ, минимум $5 | карта, BTC, USDT (TRC20) | самый дешёвый; есть бесплатный пробный объём; качество пула ниже, для HTTP-проб достаточно |

## 3. Как получить доступ (на примере Decodo)

1. Зарегистрируйтесь на decodo.com, подтвердите почту. Для пробного периода и покупки нужна карта.
2. Dashboard → Residential → выберите план Pay As You Go, купите 2 ГБ.
3. Residential → **Proxy setup**: создайте пользователя (username + password), выберите тип сессии **Rotating** (порт `7000`),
   в блоке Location выберите страну. Панель покажет готовую строку вида
   `user-<ваш_логин>-country-us:<пароль>@gate.decodo.com:7000`. Именно из неё берётся формат: страна подставляется в имя
   пользователя.
4. Проверьте из терминала, что выход действительно в нужной стране:

   ```bash
   curl -s -x "http://user-<логин>-country-ua:<пароль>@gate.decodo.com:7000" https://api.country.is/
   # ожидаем {"ip":"...","country":"UA"}
   ```

У других провайдеров формат отличается только строкой пользователя и хостом, например (скопируйте точную строку из панели
провайдера, это шаблоны):

| Провайдер | Шаблон |
|---|---|
| Decodo, резидентные | `http://user-LOGIN-country-{cc}:PASS@gate.decodo.com:7000` |
| Decodo, ISP (триал) | `http://user-LOGIN-country-{cc}:PASS@isp.decodo.com:10001`, `PROBE_PROXY_TYPE=isp` |
| IPRoyal | `http://LOGIN:PASS_country-{cc}@geo.iproyal.com:12321` |
| DataImpulse | `http://LOGIN__cr.{cc}:PASS@gw.dataimpulse.com:823` |
| Bright Data | `http://brd-customer-ID-zone-ZONE-country-{cc}:PASS@brd.superproxy.io:33335` |
| Oxylabs | `http://customer-LOGIN-cc-{CC}:PASS@pr.oxylabs.io:7777` |

`{cc}` скрипт заменяет на код страны в нижнем регистре, `{CC}` в верхнем. Регионы (штат, провинция) у каждого провайдера
задаются по-своему, поэтому для токенов вида `US-NY`, `CA-ON` строка задаётся отдельной переменной (см. ниже).

## 4. Установка и запуск

Устанавливать ничего не нужно: скрипт на Python 3.9+ из стандартной библиотеки. Секреты хранятся в `.env.probe` в корне
проекта (файл в `.gitignore`):

```bash
cat > .env.probe <<'ENV'
PROBE_PROXY_URL=http://user-LOGIN-country-{cc}:PASS@gate.decodo.com:7000
PROBE_PROXY_URL_US_NY=http://user-LOGIN-country-us-state-us_new_york:PASS@gate.decodo.com:7000
PROBE_PROXY_URL_CA_ON=http://user-LOGIN-country-ca-state-ca_ontario:PASS@gate.decodo.com:7000
PROBE_PROXY_TYPE=residential   # или isp / datacenter / mobile
PROBE_DELAY=1.0
# спецсимволы в пароле кодируйте по URL: '+' -> %2B, '@' -> %40, '/' -> %2F
ENV
set -a; source .env.probe; set +a
```

Точные имена параметров штата и провинции возьмите из Proxy setup своего провайдера.

Пробный запуск на трёх интерфейсах из одной страны:

```bash
pnpm monitor:probe -- --countries UA --only polymarket,hop,ethena
```

В выводе первой строкой идёт вантаж: `ip_country=UA asn=... verified=True by=['api.country.is', 'ipapi.co']`. Если
`verified=False` (оба гео-сервиса видят другую страну или прокси не отвечает), цели для этой страны пропускаются, и в данные
ничего не попадает.

Полный прогон первой волны стран:

```bash
pnpm monitor:probe -- --countries US,US-NY,CA-ON,GB,DE,FR,NL,PL,UA,TR,AE,SG,HK,JP,BR,AR,NG,VN,KZ,GE
```

Результат: файл `monitor/probe/out/<дата>_<тип>.json` (в `.gitignore`). Добавить его в хранилище наблюдений и пересобрать
данные сайта:

```bash
pnpm monitor:probe:merge -- monitor/probe/out/<файл>.json
pnpm monitor:build
pnpm build
```

После этого на странице «By country» у проверенных стран появится основание `observed` с датой и типом прокси, а на карточке
интерфейса — таблица «Live observations by country». Коммитьте `monitor/data/observations.json` и `src/data/interfaces.json`
вместе.

Датацентровый прогон для проверки VPN-детекта делается тем же скриптом с другим прокси:

```bash
PROBE_PROXY_URL=http://LOGIN:PASS@dc-gateway:PORT PROBE_PROXY_TYPE=datacenter pnpm monitor:probe -- --countries US,DE
```

Локальный Tor: `PROBE_PROXY_URL=socks5h://127.0.0.1:9050` сейчас не поддерживается (стандартная библиотека Python не умеет
SOCKS); для Tor нужен HTTP-шлюз, например `privoxy`, тогда `PROBE_PROXY_URL=http://127.0.0.1:8118 PROBE_PROXY_TYPE=tor`.

## 5. Как читать результат

| `ui_state` | Значение |
|---|---|
| `blocked` | HTTP 451/403 без challenge, редирект на страницу вида `/blocked`, `/restricted`, или гео-эндпоинт ответил `blocked: true` / `isRegionRestricted: true` |
| `close_only`, `feature_limited` | только из гео-эндпоинтов (`limited: true` и т.п.) |
| `challenge` | Cloudflare challenge или CAPTCHA: не тестируется, CAPTCHA не решаем |
| `ok` | главная страница отдана; клиентские гейты не оценивались |
| `error` | таймаут, 5xx; в данные сайта не попадает |

В каждом наблюдении сохраняются: страна по двум гео-сервисам, ASN, `loc=` из `/cdn-cgi/trace` для хостов за Cloudflare, цепочка
редиректов, заголовки edge (`server`, `cf-ray`), хэш и выдержка тела. Это и есть доказательство для вердикта.

## 6. Правила

- Только наблюдение: никаких логинов, обхода CAPTCHA, кошельков и транзакций.
- Один GET на цель на страну с паузой (`PROBE_DELAY`), раз в неделю. Это не нагрузка и не обход защит.
- Не пробуем санкционные юрисдикции.
- ToS части интерфейсов запрещают «обход геофенсинга». Проба ничего не обходит: запрос идёт из реальной страны и фиксирует
  ответ оператора. Тем не менее это их ToS, и запускать пробу стоит от имени проекта, не с личных аккаунтов.

## 7. Заметки по первому прогону (2026-10-08, триал Decodo ISP)

- Триал Decodo даёт **ISP-прокси** (`isp.decodo.com:10001`), а не ротируемые резидентные. Пул ограничен: AU, US, DE отвечают, UA нет. Тип прокси в данных помечен как `isp`.
- US-вантаж подтверждён тремя сервисами (AS5650 Verizon Business). DE-вантаж **не подтверждён**: ifconfig.co геолоцирует тот же IP (AS8881 1&1 Versatel) в Индию, два других сервиса в Германию. Это обычная история для ISP/датацентровых диапазонов: базы геолокации расходятся, и операторы интерфейсов (Cloudflare, Vercel) могут видеть страну иначе. Для боевого прогона нужен резидентный план.
- К `app.sky.money` и `api.sky.money` прокси Decodo не открыл туннель (`CONNECT` → 403 Forbidden от самого прокси). Это ограничение провайдера, а не Sky; такие цели остаются `error` и в данные сайта не попадают.
- Подтверждено из US: Ethena редиректит на `/restricted`, Polymarket `/api/geoblock` отвечает `blocked: true` (на сайте статус для US остаётся close-only, наблюдение его подтверждает). Euler `/api/ping` отвечает 403 без гео-формулировок и классифицируется как `unknown`.
- Главная Polymarket отдаёт тело медленно, чтение упёрлось в таймаут (`PROBE_TIMEOUT`); при повторном прогоне увеличьте до 40–60 секунд.
